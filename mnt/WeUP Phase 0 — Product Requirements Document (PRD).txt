WeUP Phase 0 — Product Requirements Document (PRD)
Product: WeUP (Event Discovery + Cultural Radar)
Phase: 0 (MVP)
Positioning: Real-time nightlife discovery via flyer ingestion, OCR, parsing, and geospatial visualization
________________


0. Executive Summary
Objective
Build a zero-friction event discovery system that transforms raw flyers into structured, searchable, map-based experiences.
Core Insight
Users do not want to “search for events.”
They want to see what’s happening right now around them.
Solution
WeUP Phase 0 ingests:
* flyer images
* social media posts
* manual uploads
Then converts them into:
* structured event data
* map-based visualization
* time-aware calendar system
________________


1. Product Vision
What WeUP is
A live cultural radar for nightlife:
* real-time
* location-aware
* visually intuitive
What WeUP is NOT (Phase 0)
* not a ticketing platform
* not a social network
* not an influencer system (yet)
________________


2. Goals & Non-Goals
2.1 Goals
* ingest event flyers
* extract structured data via OCR + parsing
* display events on a map
* provide time-based filtering
* allow event saving/bookmarking
* deliver a single-screen, no-scroll UI
________________


2.2 Non-Goals
* no user-generated event editing (beyond upload)
* no promoter profiles (Phase 0.1)
* no ticket purchasing
* no messaging or comments
* no complex recommendation engine
________________


3. Core User Personas
3.1 Explorer (Primary)
* wants to find something to do quickly
* prefers visual discovery over search
3.2 Promoter (Secondary)
* uploads flyers for visibility
* not yet identity-driven (Phase 0.1)
3.3 Admin
* moderates content
* ensures data quality
________________


4. Core User Stories
Explorer
* “Show me what’s happening tonight near me”
* “Let me filter events by time”
* “Let me quickly scan vibes”
Promoter
* “I want to upload a flyer and have it show up instantly”

5. Core Features
________________


5.1 Flyer Upload System
Description
Users upload flyer images.
Inputs
* image file
* optional metadata (title override)
Behavior
* store image
* trigger OCR pipeline
* extract text
________________


5.2 OCR + Parsing Engine
Description
Convert raw flyer into structured event data.
Extracted Fields
* event name
* date
* time
* venue name
* address
* performers (optional)
Pipeline
Upload → OCR → Text Extraction → NLP Parsing → Structured Event


________________
