WeUP Phase 0.1 — Functional Requirements Document (FRD)
Feature: Promoter Profiles + Media Feed (Photos + Short Video)
System Context: WeUP Phase 0 (Flyer ingestion + Map + Calendar)
________________


0. Document Purpose
This FRD defines the functional behavior, system interactions, data flows, constraints, and validation logic for implementing:
Promoter Profiles + Media Feed System
This document is implementation-aligned and intended for:
* Backend engineers (.NET / EF Core / gRPC)

* Frontend engineers (Vue 3 + Quasar)

* AI/automation layer (Autogen / Crawl4AI)

* QA and system validation

________________


1. System Overview
1.1 Functional Scope
The system introduces:
   * Promoter identity layer

   * Media ingestion (photo + short video)

   * Feed-based publishing model

   * Event-media association

   * Moderation + validation layer

2. Functional Modules
________________


2.1 Promoter Profile Management
FR-1: Create Promoter Profile
Description
System shall allow authenticated users to create a promoter profile.
Inputs
      * DisplayName (required)

      * Bio (optional)

      * Profile Image (optional)

      * Banner Image (optional)

      * Social links (optional)

Processing
         * Generate unique Slug

         * Store profile in DB

         * Validate image formats

Output
            * Profile created

            * Accessible via /promoters/{slug}

________________


FR-2: Update Promoter Profile
Behavior
               * User can update:

                  * Bio

                  * Images

                  * Social links

Constraints
                     * Slug cannot be modified

                     * Changes reflect immediately

________________


FR-3: Retrieve Promoter Profile
Behavior
System returns:
                        * Profile metadata

                        * Feed posts

                        * Associated events

________________


FR-4: Verification Status
Behavior
                           * Admin can set:

                              * Pending

                              * Verified

                              * Rejected

UI Effect
                                 * Verified badge visible

________________


2.2 Media Upload System
FR-5: Upload Media
Description
Promoter uploads media to system.
Inputs
                                    * File (image/video)

                                    * Caption (optional)

Validation Rules
                                       * File type must be allowed

                                       * File size must be within limits

                                       * Video duration ≤ 30 seconds

Processing
                                          * Upload to storage provider

                                          * Generate thumbnail

                                          * Store metadata

Output
                                             * MediaAsset created

________________


FR-6: Media Constraints
Type
	Limit
	Images per post
	≤ 10
	Video length
	≤ 30 sec
	Max file size
	configurable
	________________


FR-7: Media Status Handling
States
                                                * Draft

                                                * Published

                                                * Flagged

                                                * Hidden

Behavior
                                                   * Flagged media is not visible publicly

                                                   * Admin can override visibility

________________
