WeUP Phase 0.1 — Product Requirements Document (PRD)
Feature: Promoter Profiles + Media Feed (Photos + Short Video)
________________


0. Executive Summary
Objective:
Extend WeUP Phase 0 (flyer ingestion + map/calendar discovery) into an identity-driven platform by introducing Promoter Profiles with media feeds (photos + short-form video).
Why this matters:
* Converts WeUP from a utility (flyer parser) → platform (who to follow)

* Establishes trust graph (promoters → users → venues)

* Unlocks early monetization (featured profiles, paid media slots)

* Increases retention via repeat engagement

Phase Scope Constraint:
This is NOT a social network buildout. No comments, no DMs, no algorithmic feed.
________________


1. Goals & Non-Goals
1.1 Goals
   * Allow promoters to create public profiles

   * Enable multi-photo + short video uploads

   * Introduce feed-based content model

   * Allow media to be linked to events

   * Provide user-facing promoter discovery

   * Enable basic moderation + verification

   * Establish foundation for monetization

________________


1.2 Non-Goals (Strict)
      * No messaging (DMs)

      * No comments or likes

      * No livestreaming

      * No long-form video hosting

      * No recommendation algorithms

      * No influencer marketplace yet

________________


2. User Personas
2.1 Promoter
         * Hosts or markets events

         * Needs visibility and brand identity

         * Wants to showcase event quality via media

2.2 User (Consumer)
            * Browses events

            * Wants to assess “vibe”

            * Follows trusted promoters

2.3 Admin
               * Moderates content

               * Verifies promoters

               * Manages abuse and quality

________________


3. Core User Stories
Promoter
                  * Create a profile → “I want a branded identity”

                  * Upload photos/videos → “I want to show event vibe”

                  * Link media to event → “I want promotion tied to attendance”

                  * Manage feed → “I want to control my public image”

User
                     * View promoter profile → “I want to evaluate credibility”

                     * Browse media feed → “I want to see what events look like”

                     * Discover events from promoter → “I want consistency”

4. Feature Breakdown
________________


4.1 Promoter Profile
Description
A public identity page for promoters.
Required Fields
{
  "id": "guid",
  "displayName": "string",
  "slug": "string",
  "bio": "string",
  "profileImageUrl": "string",
  "bannerImageUrl": "string",
  "city": "string",
  "instagramUrl": "string",
  "tiktokUrl": "string",
  "websiteUrl": "string",
  "verificationStatus": "Pending | Verified | Rejected",
  "createdAt": "datetime"
}
Rules
                        * Unique slug per promoter

                        * One profile per account (Phase 0)

                        * Manual verification only

________________


4.2 Media System
Supported Types
                           * Images: JPG, PNG, WEBP

                           * Video: MP4, MOV, WEBM

Constraints
                              * Max video length: 30 seconds

                              * Max media per post: 10

                              * Max file size (suggested):

                                 * Images: 5MB

                                 * Video: 25MB

________________


Media Asset Schema
{
  "id": "guid",
  "promoterProfileId": "guid",
  "mediaType": "Photo | Video",
  "url": "string",
  "thumbnailUrl": "string",
  "caption": "string",
  "durationSeconds": "int",
  "visibilityStatus": "Draft | Published | Flagged",
  "createdAt": "datetime"
}
________________


4.3 Feed Post System
Description
A structured container for media.
Schema
{
  "id": "guid",

  "linkedEventId": "guid",

Relationship
